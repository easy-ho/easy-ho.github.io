개인화 추천 모델을 새 서비스에 붙이게 됐다. 기존 파이프라인은 매일 아침 배치가 전날 데이터를 S3에 올리고, 학습 서버가 3년치를 읽어 모델을 만든다. 새 서비스는 리전이 여러 개라 빌드 서버 한 대에서 순차로 돌릴 생각이었다. 그러려면 **가장 큰 리전 기준으로 서버 크기**를 정해야 했다. 그런데 지금 학습이 메모리를 얼마나 쓰는지 아무도 몰랐다.

## 개발환경 서버는 60%에서 죽었다

7.6GB짜리 개발환경 학습 서버에서 3년치를 돌렸다. 일별 CSV 1,107개 중 약 60%를 읽은 시점에 OOM. dmesg를 보니 1년 전에도 같은 패턴으로 죽은 기록이 있었다. 아무도 안 본 거다.

코드를 보니 이유가 있었다.

- 100개 파일마다 `concat([전체, 조각])`으로 합친다. 합칠 때마다 전체를 복사하니 순간 2배.
- 안 쓰는 문자열 컬럼을 끝까지 들고 간다.
- 4천만 쌍을 Python 튜플 리스트로 만든다.
- 사용자마다 Counter 객체를 만든다.

## 운영 모델을 안 건드리고 재는 법

운영 서버에서 재야 했다. 운영 서버는 매일 아침 진짜 학습을 돌리고 결과를 S3에 올린다. 측정하다가 그걸 덮어쓰면 안 된다.

- S3 저장 함수를 끈 `NO_SAVE` 모드로 사본을 돌렸다.
- 실행 전 가드. 이미 학습 중인 프로세스가 있거나, 정기 수집·학습 시간대면 중단.
- `setsid`로 세션과 분리. nohup만으로는 SSH가 끊길 때 같이 죽는 경우가 있었다.
- 5초마다 `ps -o rss`를 기록. `/usr/bin/time -v`로 피크만 보는 방법도 있다.

결과는 이렇다.

| 항목 | 값 |
|---|---|
| 원본 | 1억 3,300만 행 (파일 1,107개) |
| 중복 제거 후 | 4,165만 쌍 |
| 최대 메모리 | 21.86GB (30GB 중 73%) |
| 총 시간 | 16분 (CSV 읽기 3.5분, 학습 8분) |

5초 샘플링이라 실제 피크는 조금 더 높을 수 있다. 원본 1행당 약 165바이트로 추정했다. 측정값 하나로 낸 추정이라 다른 데이터엔 안 맞을 수 있다.

## "데이터가 늘면 언젠가 터진다"는 틀렸다

처음엔 그렇게 적었다. 데이터는 매일 쌓이니 메모리도 언젠가 부족해진다고. 지적을 받았다. **학습 창이 36개월이다.** 매일 하루치가 들어오고 하루치가 나간다. 월 경계 때문에 36~37개월 사이를 오가고 행 수는 최대 3% 정도 변동한다. 무한히 늘지 않는다.

메모리가 늘 수 있는 경우는 둘뿐이다. 거래량 자체가 늘거나, 학습 창을 넓히거나. 이걸 정확히 적고 나서야 서버 크기를 정할 수 있었다. 32GB면 원본 1.5억 행, 16GB면 7천만 행 정도까지. 추정이다.

## 추출은 생각보다 가벼웠다

새 서비스의 데이터를 뽑으려고 DB를 봤다. 거래 테이블이 생성 시각 기준 월 파티션에 생성 시각 인덱스가 있었다. EXPLAIN을 떠보니 하루 범위 조회가 해당 월 파티션 하나만 읽고 인덱스 range 스캔. 백필은 일 단위 1,130회가 아니라 월 단위 37회로 하면 된다. 운영 DB 부하가 걱정되면 `COUNT(DISTINCT)` 대신 통계 추정치를 쓰거나 리플리카에서.

학습에 실제로 영향을 주는 컬럼은 사용자 ID와 작품 ID 둘뿐이었다. 나머지는 정렬과 중복 제거에만 쓴다. 이걸 알고 나니 데이터팀에 요청할 양식이 짧아졌다.

## 키 대신 역할

"버킷 만들고 액세스 키 발급받으면 되나"에서 키 발급은 하지 말자고 했다. 키는 서버나 설정 파일에 평문으로 남는다. 학습 서버는 인스턴스 프로파일(기존 서버도 이미 그렇게 S3에 붙고 있었다), 서빙 파드는 IRSA, 데이터를 넣어주는 팀에는 버킷 정책으로 쓰기 권한만. 주체별로 필요한 권한을 표로 만들어 요청서에 넣었다. 학습은 입력 읽기와 모델 읽기·쓰기, 적재는 입력 쓰기, 서빙은 모델 읽기.

리전 여러 개의 데이터가 한 서버에 모이는 건 별도 문제다. 국외 이전 검토가 필요한 리전이 있어서 "확인 안 되면 해당 리전은 리전 안에서 빌드"로 적어두고 넘겼다.

## 정리

- 사양을 정하기 전에 지금 얼마나 쓰는지부터 잰다. 측정 한 번이 추측 열 번보다 낫다.
- 운영에서 잴 땐 출력을 끄고, 시간대를 피하고, 세션과 분리한다.
- "계속 늘어난다"는 말은 창 크기를 확인하고 나서 한다.
- 키 발급은 마지막 수단이다. 역할로 되면 역할로.
